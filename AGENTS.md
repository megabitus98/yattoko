# AGENTS.md

Guidance for coding agents (and people) working in this repository. `CLAUDE.md` imports this file; keep one copy of the facts here.

ytdlbot is a Telegram bot for a small allow-listed group: send a link in a private chat, get the video back. Kurigram (a pyrogram fork, imported as `pyrogram`) for Telegram, yt-dlp for downloads, SQLite for settings. English UI. Fork of Katze-942/ytdlbot, itself a fork of tgbot-collection/ytdlbot (credit in `README.md` and `NOTICE`).

## Commands

- Install: `uv sync` (Python 3.12, from `uv.lock`). Edit dependencies in `pyproject.toml`, then `uv lock`.
- Unit tests: `uv run pytest -q`. No network, no Telegram. `tests/conftest.py` sets safe env values (`APP_ID=1`, `OWNER=1`, `AUTHORIZED_USER=1,2`, `DATA_DIR`/`TMPFILE_PATH`/`DB_DSN`/`COOKIES_DIR` under a temp dir) before any app module is imported, so a local `.env` never reaches the tests.
- Repository checks: `uv run pytest -q tests/repo` (README, NOTICE, removed files, the fork notice line; they need a full git checkout, and `.dockerignore` keeps them out of the image).
- Image: `docker build --target test -t ytdlbot:test . && docker run --rm ytdlbot:test` runs the unit tests against the runtime layers. `docker build --target runtime -t ytdlbot:dev .` builds the shipped image.
- Self-check: `python main.py --self-check` (in `src/` or the image) prints yt-dlp, curl-cffi and kurigram versions, whether impersonation works and whether `DATA_DIR` and `TMPFILE_PATH` are writable, as JSON; exit 1 if any check fails. It creates no Telegram client.
- Local run: `docker compose up -d` (one service, image `ytdlbot:local`, volumes for `/data` and `/tmp`, read-only root). Without Docker: set `DATA_DIR` and `TMPFILE_PATH` to local paths in `.env`, then `cd src && uv run python main.py`.
- Format: `black`.
- Pipeline: `.github/workflows/ci.yml` (PRs from this repository: `tests/repo`, unit tests in the `test` image, then pushes `ghcr.io/<repo>:sha-<head sha>`; the job id `unit` is the check name), `.github/workflows/merge-and-promote.yml` (every 15 min: merges one green Dependabot uv PR, copies the tested digest to `stable`), `.github/dependabot.yml`; `tests/repo/test_pipeline_files.py` checks them. `deploy/` holds a placeholder-only Kubernetes example.

## Layout

- `src/main.py`: plain handler functions; download handlers call `submit_download()`, which sends the progress message, hands the download to the module-level `JOBS = JobQueue(MAX_PARALLEL_JOBS)` and returns (a queued job's message reads `BotText.queued`); errors are replied from inside the job. `tests/conftest.py` replaces `JOBS` with an inline queue so handler tests stay synchronous. Also `handler_table() -> list[HandlerSpec]` (`HandlerSpec = tuple[type, Callable, Filter | None, int]`: handler class, callback, filters, group) and `create_app() -> Client`, which registers every entry with `app.add_handler(cls(callback, filters), group)`. Importing `main` builds no client. Tests about which handlers exist inspect `handler_table()`, not `app.dispatcher.groups`. With `ENABLE_VIP` only, `handler_table()` adds `VIP_HANDLERS` (`/buy`, the `BUY_CHOICES` callbacks priced from that dict, pre-checkout, successful payment) before the catch-all text handler, `/start` shows the quota, and `create_app()` starts `scheduler`, an APScheduler `BackgroundScheduler` running `database.model.reset_free` daily at 00:00.
- `src/utils/access.py`: the access guard. `GUARDS` puts one message guard, one callback guard and one pre-checkout guard at dispatcher group -1, before every other handler. A sender who is not in `OWNER` or `AUTHORIZED_USER` ends dispatch with `stop_propagation()`; in a private chat they get their Telegram ID at most once a day (in-memory throttle). Messages without a sender are dropped. Group messages are dropped unless `ENABLE_GROUPS` is on.
- `src/config/config.py`: every env var is read here, strictly. Blank means default; a bad ID list, boolean or integer raises `ConfigError` at import, so the bot does not start. `OWNERS`, `AUTHORIZED_USERS`, `ALLOWED_USERS` are frozensets; empty means nobody. Feature switches: `ENABLE_SEARCH`, `ENABLE_DIRECT`, `ENABLE_ARIA2`, `ENABLE_SPDL`, `ENABLE_STATS`, `ENABLE_GROUPS`, `M3U8_SUPPORT`, `ENABLE_VIP` (with `PROVIDER_TOKEN`, `FREE_DOWNLOAD` default 3, `TOKEN_PRICE` default 10 and unused, as upstream), all false by default. `ENABLE_FFMPEG` drives the H.264 conversion (`engine/transcode.py`); `REENCODE_MAX_SECONDS` (default 300, 0 or more) is the longest video it converts. `RCLONE_PATH` and `ENABLE_FFMPEG` are restored from upstream and read, but nothing uses them (upstream master does not either). `check_paths()` refuses a `TMPFILE_PATH` that overlaps `DATA_DIR`. Jobs: `MAX_PARALLEL_JOBS` (default 2, at least 1), `TMP_BUDGET` (bytes, default `MAX_PARALLEL_JOBS` × 4500 MiB), `JOB_TIMEOUT` (seconds, default 2700), `OWN_PUBLIC_IPS` (frozenset of normalised IP strings; `parse_ip_list` never echoes the value). `PROXY_EXITS` (`parse_exits`: ordered list, default `["direct"]`, items `direct` or http(s) proxy URLs) and `PROXY_PIN` (`parse_pins`: `site=exit` dict, each exit in `PROXY_EXITS`). No `ConfigError` message repeats the value. `COOKIES_DIR` (default `/cookies`) holds one cookies file per site. Exception: `POTOKEN` is read with `os.getenv` in `engine/generic.py`.
- `src/config/constant.py`: `BotText`, every user-facing string. A test fails on Cyrillic anywhere in `src/`.
- `src/config/__init__.py`: `load_dotenv()`, re-exports `config.config` and `config.constant`, and installs the root log handler with `utils.redact.RedactingFormatter`, which masks the bot token, `PROVIDER_TOKEN`, every configured proxy exit URL and its host name, credentials in URLs (up to the last `@` of the authority) and cookie values in every formatted line, tracebacks included. Importing anything from `config` has these side effects.
- `src/engine/__init__.py`: `youtube_entrance` (`engine/generic.py`, yt-dlp, the path for every site), `direct_entrance` (`/direct`, requests or aria2) and `special_download_entrance` (`/spdl`, pixeldrain, krakenfiles). Instagram goes through yt-dlp like every other site.
- `src/engine/sites.py`: `site_for_url()` names the site of a link from the first non-generic yt-dlp extractor that matches it, offline (`youtube`, `instagram`, `tiktok` for their extractor families, else the extractor key in lower case, `generic` if none); `display_name()` gives "YouTube", "Instagram", "TikTok" or title case.
- `src/engine/cookies.py`: `cookie_options()` reads `<COOKIES_DIR>/<site>.txt` and returns `{"cookiefile": io.StringIO(text)}`, or `{}` when the file is missing or empty. Never pass the mounted path to yt-dlp: it writes the jar back to its cookiefile on close. Build a fresh copy for every `YoutubeDL` and never read the copy back. `instagram_session_present()` checks the jar for `sessionid`.
- `src/engine/base.py`: `BaseDownloader`. `__init__` runs the host check first and starts the job's `JOB_TIMEOUT` clock. `start()` looks up the file cache (key: url, quality, format, codec, SponsorBlock, fixed in `__init__`), reuses the Telegram `file_id` on a hit, otherwise runs `_start()` (download, then upload). `check_limits()` (from `download_hook` and the `/direct` requests loop) raises `TooLarge` when the bytes so far or the total pass `TG_NORMAL_MAX_SIZE` or `TMPFILE_PATH` holds more than `TMP_BUDGET`, and `JobTimeout` after `JOB_TIMEOUT`; `_download_fitting()` checks the finished files and downloads once more one step down `QUALITIES` before raising `TooLarge`. A `TooLarge` edits the progress message to `BotText.too_large`. Quality, format, codec and SponsorBlock settings are read by the requesting user's ID (in a group, the sender of the message the bot replied to), not the chat ID. The per-job temp dir under `TMPFILE_PATH` is removed in `finally`. A failure is logged and the progress message is edited once to the classified text from `engine/errors.py`; after a `login_required` or `blocked` reply `engine.errors.tell_owners()` sends the owner notice. A `RefusedContent` edits it to `BotText.refused`; a Telegram `FloodWait` goes up to the job closure in `main.submit_download()`, which tells the user to wait and re-submits the job to `JOBS` from a daemon `threading.Timer` after the wait (no thread sleeps through it). With `ENABLE_VIP`, `start()` calls `check_quota` first (`QuotaExhausted` edits the message to `BotText.quota_exhausted`) and `use_quota` after a file was sent, cache hits included. Sending as video tries video, animation, audio, photo in order and raises `RuntimeError` if all fail (kurigram 2.2.27 raises on a failed upload).
- `src/engine/generic.py`: `build_format_options()` builds the format string (size-capped ladder, then one file with video and sound, then video only, then audio only), `format_sort` with the codec first (H.264 for "auto"), the quality setting as `res:<N>` (yt-dlp's res is the smaller side, so a vertical 1080x1920 video is 1080p; no height filters) and `merge_output_format: mp4`; Google Drive links get `source/` in front, with the codec setting on auto Instagram links get `best/` (its single files are H.264 with sound but yt-dlp lists their codecs as unknown, so the sort alone would pick the VP9 streams; without a login they stop at 720p, 1080p exists only as VP9) and TikTok sorts H.265 first (its H.264 files stop at 540p with 32 kb/s sound, its H.265 files reach 1080p with 64 kb/s). `PREFERRED_AUDIO_LANG` picks the audio track by prefix (`en` also matches `en-US`); empty means the original. `YoutubeDownload._download()` tries the exits from `engine/proxy.py` `exits_for(site, PROXY_EXITS, PROXY_PIN)` in order (a pinned site gets only its exit): host check, then `attempt()`; only a `blocked` failure moves on to the next exit (with an emptied temp dir), any other error or the last exit's error goes up to `BaseDownloader.start()`. Exits are logged and recorded for the owner notice as `exit_label()` (`direct`, `exit 2`), never as URLs. `attempt()` is one download attempt in one `YoutubeDL`: proxy from `ydl_proxy(exit)`, a fresh cookies copy, `extract_info(download=False, process=False)`, `url` pointers followed, then `process_ie_result(download=True)` in the same instance. With Instagram cookies that carried `sessionid`, a jar without it at the end of the attempt (yt-dlp drops it when the cookies stopped working) calls `on_cookies_expired`, which sends a `cookies_expired` notice. yt-dlp logs through the root logger; no verbose mode.
- `src/engine/transcode.py`: `to_h264(path, max_side, max_seconds, timeout, on_start=None)` converts the main video stream to H.264 in place (libx264 veryfast CRF 20, 2 threads; `-map 0 -c copy` keeps sound and the embedded cover, which the upload uses as thumbnail; the main stream is addressed by its index) when `playable()` says no (anything but H.264 or H.265 tagged hvc1) and the file is at most `max_seconds` long; returns False when nothing was needed and raises `TooLong` when it would need converting but is longer (or its length is unknown). A timeout or ffmpeg error leaves the source and raises. With `ENABLE_FFMPEG`, `YoutubeDownload._choose()` hands `attempt(choose=...)` the quality-first options (`build_format_options(quality_first=True)`: sort `hdr:sdr,res:<N>` first, no per-site rules) for videos up to `REENCODE_MAX_SECONDS` and for videos whose length the site does not give (Instagram); `_download()` converts before `_download_fitting()` checks the size, and on `TooLong` after a quality-first download it empties the job dir and downloads once more H.264 first; the progress message reads `BotText.converting` while ffmpeg runs. The default quality setting is 1440p.
- `src/engine/jobs.py`: `JobQueue(max_parallel)`, a thread pool; `submit(fn)` returns the job's queue position (0: starts now) and logs exceptions nobody would read; `shutdown(wait)` drops jobs that have not started. Also `TooLarge` and `JobTimeout` (plain `Exception`s on purpose: yt-dlp turns an `OSError` raised in a hook into `UnavailableVideoError`).
- `src/utils/netcheck.py`: `check_url(url, own_ips, resolver=socket.getaddrinfo)` raises `BlockedHost` unless the link is http(s) with a host whose IPv4 addresses (asked with `AF_INET`, so dual-stack hosts pass) are all global, not multicast and not in `OWN_PUBLIC_IPS`. Called in `BaseDownloader.__init__` and before every `attempt()`, proxied ones too; `classify()` maps `BlockedHost` to `unavailable`. Tests never resolve names: `tests/conftest.py` swaps the resolver default for an offline one.
- `src/health.py`: `start_heartbeat(client, path, interval)` (daemon thread: `get_me()`, then touch `/tmp/healthy`, every 60 s); `python health.py` exits 0 while the file is younger than 180 s. Standard library only. `main.serve()` starts it after `app.start()`, then runs `check_impersonation()` in a thread (on the client's loop kurigram's sync methods return coroutines and send nothing), which sends an `impersonation_missing` notice when yt-dlp has no impersonation target.
- `src/utils/notify.py`: `notify_owners(client, owners, site, kind, details, *, cookies, exits)` claims the `(site, kind)` pair first (`database.model.claim_notice`, at most once per 24 h, stored in SQLite so a restart does not re-send), then messages each owner separately as plain text (`BotText.owner_notice`, redacted, details cut to 300 characters) and returns how many sends worked; it never raises. Kinds: `login_required`, `blocked`, `cookies_expired`, `impersonation_missing`. `send_to_owners()` is the per-owner loop (also used for the flood-wait message). Each owner must have sent `/start` to the bot once.
- `src/database/model.py`: SQLAlchemy `User` (with upstream's `free`, `paid`, `config` columns), `Setting`, `Payment` (table `payments`) and `OwnerNotice` (unique `(site, kind)`, `last_sent` in UTC); `claim_notice` is one insert-or-update statement, so two jobs failing at once cannot both claim; engine from `DB_DSN` (default SQLite in `DATA_DIR`, WAL, 30 s busy timeout); `init_user` is insert-or-ignore; all access through `session_manager()`. Upstream's quota functions (`get_free_quota`, `get_paid_quota`, `check_quota` and `use_quota` raising `QuotaExhausted`, `reset_free`, `credit_account`) are called only with `ENABLE_VIP`. `create_schema()` runs at import: `create_all`, then `ensure_columns` for `ADDED_COLUMNS` (the users quota columns), always, since every `User` query selects them. `src/database/migrate.py`: check-and-`ALTER` helper for columns added later. `src/database/cache.py`: `get_cache()` returns one client for every job: Redis at `REDIS_HOST`, fakeredis when unset or unreachable (two fakeredis clients without a shared server would not see each other's data).
- `src/selfcheck.py`: the `--self-check` logic.

## Rules

- Download errors: `engine/errors.py` `classify()` sorts a failure into `login_required`, `blocked`, `unavailable` or `other` (exception types first, then pinned message patterns, tested in `tests/test_errors.py`), and `user_message()` gives the reply (`other` is `BotText.error`). Engines raise instead of replying; `BaseDownloader.start()` or the handler's `reply_error()` replies once and logs the traceback. Never put exception text, paths, hostnames or proxy details in a Telegram message. Never log secrets (bot token, `APP_HASH`, cookie values, proxy credentials).
- Every source file changed in this fork carries one line under its header: `# Modified 2026 by megabitus98 (fork): <what changed>`. Keep existing `__author__` lines and the `By @BennyThink` banner (Apache-2.0, section 4(c)). `tests/repo` checks the line.
- No private details in the repository: no IP addresses, Telegram IDs, hostnames or proxy URLs of the owner. Examples use `123456789` and `http://proxy.example:8080`.
- Unit tests make no network calls and never connect to Telegram.
- Settings callbacks are matched by anchored regexes built from dicts in `main.py` and saved under the presser's user ID.
- Not supported on purpose: playlists, channels and live streams. `attempt()` raises `RefusedContent` on a `playlist`, `multi_video` or live result before anything is downloaded, and its `match_filter` stops any playlist entry or live video that gets past that check; the user gets `BotText.refused`. yt-dlp runs with `noplaylist`, so `watch?v=x&list=y` is the video. Instagram carousel posts are playlists and are refused too. yt-dlp uses `source_address: 0.0.0.0` (IPv4 only).
- The image runs as uid 10001 with a read-only root: `HOME`, `XDG_CACHE_HOME` and `DENO_DIR` point under `/tmp`; `/data` is the only other writable path.
