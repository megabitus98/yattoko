# AGENTS.md

Guidance for coding agents (and people) working in this repository. `CLAUDE.md` imports this file; keep one copy of the facts here.

ytdlbot is a Telegram bot for a small allow-listed group: send a link in a private chat, get the video back. Kurigram (a pyrogram fork, imported as `pyrogram`) for Telegram, yt-dlp for downloads, SQLite for settings. English UI. Fork of Katze-942/ytdlbot, itself a fork of tgbot-collection/ytdlbot (credit in `README.md` and `NOTICE`).

## Commands

- Install: `uv sync` (Python 3.12, from `uv.lock`). Edit dependencies in `pyproject.toml`, then `uv lock`.
- Unit tests: `uv run pytest -q`. No network, no Telegram. `tests/conftest.py` sets safe env values (`APP_ID=1`, `OWNER=1`, `AUTHORIZED_USER=1,2`, `DATA_DIR`/`TMPFILE_PATH`/`DB_DSN`/`COOKIES_DIR` under a temp dir) before any app module is imported, so a local `.env` never reaches the tests.
- Repository checks: `uv run pytest -q tests/repo` (README, NOTICE, removed files, the fork notice line; they need a full git checkout, and `.dockerignore` keeps them out of the image).
- Image: `docker build --target test -t ytdlbot:test . && docker run --rm ytdlbot:test` runs the unit tests against the runtime layers. `docker build --target runtime -t ytdlbot:dev .` builds the shipped image.
- Self-check: `python main.py --self-check` (in `src/` or the image) prints yt-dlp, curl-cffi and kurigram versions, whether impersonation works and whether `DATA_DIR` and `TMPFILE_PATH` are writable, as JSON; exit 1 if any check fails. It creates no Telegram client.
- Local run: `docker compose up -d` (one service, image `ytdlbot:local`, volumes for `/data` and `/tmp`, read-only root). Without Docker: set `DATA_DIR` and `TMPFILE_PATH` to local paths in `.env`, then `cd src && uv run python main.py`.
- Format: `black`.

## Layout

- `src/main.py`: plain handler functions, `handler_table() -> list[HandlerSpec]` (`HandlerSpec = tuple[type, Callable, Filter | None, int]`: handler class, callback, filters, group) and `create_app() -> Client`, which registers every entry with `app.add_handler(cls(callback, filters), group)`. Importing `main` builds no client. Tests about which handlers exist inspect `handler_table()`, not `app.dispatcher.groups`.
- `src/utils/access.py`: the access guard. `GUARDS` puts one message guard and one callback guard at dispatcher group -1, before every other handler. A sender who is not in `OWNER` or `AUTHORIZED_USER` ends dispatch with `stop_propagation()`; in a private chat they get their Telegram ID at most once a day (in-memory throttle). Messages without a sender are dropped. Group messages are dropped unless `ENABLE_GROUPS` is on.
- `src/config/config.py`: every env var is read here, strictly. Blank means default; a bad ID list, boolean or integer raises `ConfigError` at import, so the bot does not start. `OWNERS`, `AUTHORIZED_USERS`, `ALLOWED_USERS` are frozensets; empty means nobody. Feature switches: `ENABLE_SEARCH`, `ENABLE_DIRECT`, `ENABLE_ARIA2`, `ENABLE_SPDL`, `ENABLE_STATS`, `ENABLE_GROUPS`, `M3U8_SUPPORT`, all false by default. `check_paths()` refuses a `TMPFILE_PATH` that overlaps `DATA_DIR`. `COOKIES_DIR` (default `/cookies`) holds one cookies file per site. Exception: `POTOKEN` is read with `os.getenv` in `engine/generic.py`.
- `src/config/constant.py`: `BotText`, every user-facing string. A test fails on Cyrillic anywhere in `src/`.
- `src/config/__init__.py`: `load_dotenv()`, re-exports `config.config` and `config.constant`, and installs the root log handler with `utils.redact.RedactingFormatter`, which masks the bot token, credentials in URLs and cookie values in every formatted line, tracebacks included. Importing anything from `config` has these side effects.
- `src/engine/__init__.py`: `youtube_entrance` (`engine/generic.py`, yt-dlp, the path for every site), `direct_entrance` (`/direct`, requests or aria2) and `special_download_entrance` (`/spdl`, pixeldrain, krakenfiles). Instagram goes through yt-dlp like every other site.
- `src/engine/sites.py`: `site_for_url()` names the site of a link from the first non-generic yt-dlp extractor that matches it, offline (`youtube`, `instagram`, `tiktok` for their extractor families, else the extractor key in lower case, `generic` if none); `display_name()` gives "YouTube", "Instagram", "TikTok" or title case.
- `src/engine/cookies.py`: `cookie_options()` reads `<COOKIES_DIR>/<site>.txt` and returns `{"cookiefile": io.StringIO(text)}`, or `{}` when the file is missing or empty. Never pass the mounted path to yt-dlp: it writes the jar back to its cookiefile on close. Build a fresh copy for every `YoutubeDL` and never read the copy back. `instagram_session_present()` checks the jar for `sessionid`.
- `src/engine/base.py`: `BaseDownloader`. `start()` looks up the file cache (key: url, quality, format, codec), reuses the Telegram `file_id` on a hit, otherwise runs `_start()` (download, then upload). Quality, format and codec settings are read by the requesting user's ID (in a group, the sender of the message the bot replied to), not the chat ID. The per-job temp dir under `TMPFILE_PATH` is removed in `finally`. A failure is logged and the progress message is edited once to the classified text from `engine/errors.py`; a `RefusedContent` edits it to `BotText.refused`; a Telegram `FloodWait` goes up to the handler instead. Sending as video tries video, animation, audio, photo in order and raises `RuntimeError` if all fail (kurigram 2.2.27 raises on a failed upload).
- `src/engine/generic.py`: `build_format_options()` builds the format string (size-capped ladder), `format_sort` with the codec first (H.264 for "auto") and `merge_output_format: mp4`; Google Drive links get `source/` in front. `PREFERRED_AUDIO_LANG` picks the audio track by prefix (`en` also matches `en-US`); empty means the original. `attempt()` is one download attempt in one `YoutubeDL`: proxy from `engine/proxy.py` `ydl_proxy(exit)`, a fresh cookies copy, `extract_info(download=False, process=False)`, `url` pointers followed, then `process_ie_result(download=True)` in the same instance. yt-dlp logs through the root logger; no verbose mode.
- `src/database/model.py`: SQLAlchemy `User` and `Setting`; engine from `DB_DSN` (default SQLite in `DATA_DIR`, WAL, 30 s busy timeout); `init_user` is insert-or-ignore; all access through `session_manager()`. `src/database/migrate.py`: check-and-`ALTER` helper for columns added later. `src/database/cache.py`: Redis at `REDIS_HOST`, fakeredis when unset or unreachable.
- `src/selfcheck.py`: the `--self-check` logic.

## Rules

- Download errors: `engine/errors.py` `classify()` sorts a failure into `login_required`, `blocked`, `unavailable` or `other` (exception types first, then pinned message patterns, tested in `tests/test_errors.py`), and `user_message()` gives the reply (`other` is `BotText.error`). Engines raise instead of replying; `BaseDownloader.start()` or the handler's `reply_error()` replies once and logs the traceback. Never put exception text, paths, hostnames or proxy details in a Telegram message. Never log secrets (bot token, `APP_HASH`, cookie values, proxy credentials).
- Every source file changed in this fork carries one line under its header: `# Modified 2026 by megabitus98 (fork): <what changed>`. Keep existing `__author__` lines and the `By @BennyThink` banner (Apache-2.0, section 4(c)). `tests/repo` checks the line.
- No private details in the repository: no IP addresses, Telegram IDs, hostnames or proxy URLs of the owner. Examples use `123456789` and `http://proxy.example:8080`.
- Unit tests make no network calls and never connect to Telegram.
- Settings callbacks are matched by anchored regexes built from dicts in `main.py` and saved under the presser's user ID.
- Not supported on purpose: playlists, channels and live streams. `attempt()` raises `RefusedContent` on a `playlist`, `multi_video` or live result before anything is downloaded, and its `match_filter` stops any playlist entry or live video that gets past that check; the user gets `BotText.refused`. yt-dlp runs with `noplaylist`, so `watch?v=x&list=y` is the video. Instagram carousel posts are playlists and are refused too. yt-dlp uses `source_address: 0.0.0.0` (IPv4 only).
- The image runs as uid 10001 with a read-only root: `HOME`, `XDG_CACHE_HOME` and `DENO_DIR` point under `/tmp`; `/data` is the only other writable path.
